# MarketMaker

A native PySide6 desktop app for turning local Agent Skills into a shareable plugin marketplace.

```powershell
uv sync --group dev
uv run agentskills-marketmaker
```

1. Add skill locations. The initial list contains `~/.agents/skills` and `~/.codex/skills`; changes are saved with Qt settings.
2. Click **Index locations**. The scan finds skill folders recursively, including linked folders, and indexes each resolved folder once. A skill folder is a directory with `SKILL.md`; its supporting directories are not indexed as separate skills.
3. Search and check skills. Selecting a row displays its instructions. Filtering leaves checked skills selected, including hidden rows.
4. Set marketplace ID, display name, plugin version, and publisher. The preview shows the catalog and each plugin manifest.
5. Click **Export marketplace** and choose a parent folder. A new folder named after the marketplace ID is created. Existing output folders are never overwritten.
6. In **Share via Git**, enter an existing empty remote and click **Commit and push export**. Git must be installed with a configured identity and credentials. This initializes the export as a repository, commits all exported files, and pushes `main`.

Each skill becomes one independently installable plugin:

```text
team-skills/
  .agents/plugins/marketplace.json
  plugins/
    example-skill/
      plugin.json
      skills/example-skill/
        SKILL.md
        scripts/
        references/
        assets/
  README.md
```

The entire skill directory is copied without rewriting its contents. Linked content is materialized. Files outside that directory referenced by absolute paths, external MCP configurations, tools, credentials, and runtime dependencies are not bundled. The app does not convert host-specific instructions into portable ones or assign new licenses to copied files.

Team members add a published repository with `codex plugin marketplace add OWNER/REPOSITORY`, then install from its marketplace in the ChatGPT desktop Plugins Directory. A Git push does not publish to the universal public directory or grant ChatGPT workspace access.

The original `uv run marketmaker` command remains available.

## Windows installer

The Inno Setup installer is `dist/agentskills-marketmaker-0.2.0-setup.exe`. It installs per user on Windows x64-compatible systems, with a Start menu shortcut and optional desktop shortcut. Internet access is required during installation.

Setup bundles only the MarketMaker application, its metadata, and launcher configuration. Inno's native download and ZIP extraction features retrieve these pinned private dependencies:

- CPython 3.12.10's Windows x64 embeddable runtime, matching the project's Python 3.12 target.
- The Windows CPython 3.12-compatible wheels for every runtime dependency in `uv.lock`, including Qt/PySide6 and their DLLs.
- MinGit 2.56.0.3 x64 for Git publishing.

Every download has a fixed SHA-256 hash and extracted size in `packaging/generated/downloads.iss`. The manifest `packaging/generated/payloads.json` records URLs, hashes, download sizes, and installed sizes. Setup downloads about 311 MB (296 MiB); those archives are not embedded in the installer. Runtime license files and wheel metadata are retained.

Python and Git stay inside the app directory. The installed launcher uses its private Git by changing only its own process environment; machine and user PATH settings are unchanged. Git identity, remote access, and credentials still need to be configured for publishing. No pip, uv, Python, or Git installation is needed to launch the installed app. The installer does not install the Codex client.

Build with the locked development environment and Inno Setup 6.7.3 or newer:

```powershell
uv sync --group dev
uv run python packaging/prepare.py
& 'C:\path\to\Inno Setup 6\ISCC.exe' packaging/installer.iss
```

Use the actual path of your installed compiler. The preparation step downloads archives to measure their extracted sizes and stages only the application wheel under `build/app-<version>`. Use a clean staging directory when the application file inventory changes. The installer contains no package-manager bootstrap, fallback URL, or custom retry logic. Inno verifies downloads and reports installation failures directly.

The installer is unsigned. Installing it again updates the same per-user application identity. Uninstall removes the installed runtime and leaves the app's Qt user settings and exported marketplaces intact. The installed shortcut uses Python's `-B` option to avoid leaving generated bytecode caches in the installation directory.

Packaging follows the official [Inno download and extraction documentation](https://jrsoftware.org/ishelp/topic_filessection.htm), [Python embeddable distribution guidance](https://docs.python.org/3.12/using/windows.html#the-embeddable-package), and [Git for Windows release](https://github.com/git-for-windows/git/releases/tag/v2.56.0.windows.3).

## Specification baseline

Reviewed on **2026-10-25**:

- [OpenAI plugin packaging and marketplace metadata](https://developers.openai.com/plugins/build/plugins): root `plugin.json`, `.agents/plugins/marketplace.json`, repo-root-relative plugin paths, install policies, and OpenAI presentation extensions.
- [Agent Plugins 1.0.0](https://agent-plugins.org/specification) and its [official manifest JSON Schema](https://agent-plugins.org/schemas/1.0.0/plugin.schema.json): portable manifests and automatic discovery of `skills/`. The official schema is bundled unchanged under `src/marketmaker/schemas/` for offline manifest validation.
- [Agent Skills specification](https://agentskills.io/specification): `SKILL.md` YAML metadata and supporting files.
- [OpenAI skill authoring](https://learn.chatgpt.com/docs/build-skills): host skill usage and authoring guidance.

Marketplace output follows OpenAI's documented catalog format; the bundled official JSON Schema validates plugin manifests, not the marketplace catalog. This is a dated implementation baseline, not an automatic specification updater. No legacy manifest overlays are generated.

## Execution policy

The primary path is deliberately fail-fast. Filesystem, YAML, schema, and Git failures propagate without catches, retries, substitutions, or rollback. A failed copy or push can leave partial output. Start from a new export folder for a new attempt. Duplicate selected skill names are rejected by the native schema validator rather than silently renamed.

The UI uses native Qt widgets, system fonts and palette, standard keyboard focus and checkbox states, a native title bar, and resizable splitters. No custom theme or browser runtime is involved. Index, copy, and Git operations run synchronously in this initial version; large source trees or slow remotes can block the window. Run from a terminal to see native Python and Git diagnostics.

## Verification

```powershell
uv run pytest
uv run ruff check .
```

Tests cover complete directory export, source preservation, generated paths, official manifest schema validation, duplicate selections, missing roots, existing destinations, filtered Qt selection, remembered locations, and publishing to a temporary local Git remote. Live GitHub credentials and installation in a team member's client require end-to-end verification in that environment.
